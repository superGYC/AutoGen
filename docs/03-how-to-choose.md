# 03 — 如何选择：决策矩阵与场景指南

## 🎯 决策树

```
                    你要做多智能体系统？
                          │
            ┌─────────────┼─────────────┐
            ▼             ▼             ▼
       流程可控性    团队/角色感      对话/探索性
       最重要？      最重要？         最重要？
            │             │             │
            ▼             ▼             ▼
      ┌─────────┐   ┌─────────┐   ┌─────────┐
      │LangGraph│   │ CrewAI  │   │ AutoGen │
      └─────────┘   └─────────┘   └─────────┘
```

---

## 📋 按场景选框架

### 🏦 金融 / 医疗 / 法律（合规行业）

**推荐：LangGraph**

为什么：
- 每一步都可审计、可回滚
- Human-in-the-loop 原生支持（审批节点）
- 状态 checkpoint = 故障恢复 = 业务连续性

例子：
```
客户申请贷款
  → 信用检查节点（自动）
  → 人工审批节点（human-in-the-loop）
  → 风控模型节点（自动）
  → 结果通知节点
```

---

### ✍️ 内容生产 / SEO / 营销

**推荐：CrewAI**

为什么：
- 研究员 → 写手 → 编辑 → SEO 优化师，天然是角色分工
- 快速搭建，PM 也能写
- 模板化 Crew 可复用

例子：
```
研究员: "找出 10 个长尾关键词"
写手: "基于关键词写 5 篇博客大纲"
编辑: "润色并统一风格"
SEO: "优化标题和 meta description"
```

---

### 💻 代码生成 / 调试 / 自动化脚本

**推荐：AutoGen**

为什么：
- 代码执行器（Code Executor）可以直接跑 Python/SQL
- Agent 之间可以 " debate " — "这段代码有 bug"、"我改一下"
- 迭代优化的对话模式非常适合 coding

例子：
```
程序员 Agent: "写个爬虫抓取数据"
测试 Agent: "跑一下，报错了，索引越界"
程序员 Agent: "我加个异常处理"
测试 Agent: "再跑，通过了"
```

---

### 🎧 客服 / 售后 / 咨询

**推荐：LangGraph**

为什么：
- 需要明确的流程：问候 → 意图识别 → 知识库查询 → 解决方案 → 满意度 → 工单
- 遇到复杂问题需要升级人工 = human-in-the-loop
- 会话持久化 = 用户下次来能接着聊

---

### 🔬 学术研究 / 数据分析

**推荐：AutoGen**

为什么：
- 探索性任务，流程不明确，需要反复讨论
- "这个数据趋势怎么解释？"、"换个模型试试"、"对照组怎么设？"
- 可以接 Jupyter Notebook 直接执行代码

---

### 📊 企业流程自动化（ERP/CRM 集成）

**推荐：LangGraph**

为什么：
- 对接多个系统 = 复杂的分支逻辑
- 需要事务性保证（要么全成功，要么回滚）
- 需要详细的执行日志供审计

---

## 👥 按团队能力选

| 团队情况 | 推荐 | 理由 |
|---------|------|------|
| "我们 2 个后端，1 个 PM，没有 ML 专家" | **CrewAI** | 文档友好，Python 基础就能上手 |
| "我们有算法工程师，喜欢精确控制" | **LangGraph** | 回报是学习曲线换来的可控性 |
| "我们在做 research，需要快速实验" | **AutoGen** | 弹性最大，适合探索未知 |
| "我们要上生产，有合规要求" | **LangGraph** | 稳定、可审计、可恢复 |
| "我们先做个 MVP 验证方向" | **CrewAI** | 最快出活 |

---

## 💰 按预算选

| 预算敏感度 | 推荐 | 原因 |
|-----------|------|------|
| "能省则省" | **LangGraph** | 单次 $0.08，调用次数最少 |
| "中等预算，想要性价比" | **CrewAI** | 单次 $0.15，平衡 |
| "研究经费充足，要最好效果" | **AutoGen** | 单次 $0.45，但对话质量高 |

---

## 🔀 混合使用？完全可以

这三个框架不是互斥的。你可以：

```
┌──────────────────────────────────────┐
│  整个系统用 LangGraph 编排             │
│  ┌──────────┐  ┌──────────┐          │
│  │ 子流程 A │  │ 子流程 B │          │
│  │ (CrewAI) │  │ (AutoGen)│          │
│  │ 内容团队 │  │ 代码调试 │          │
│  └──────────┘  └──────────┘          │
└──────────────────────────────────────┘
```

比如：
- 主流程用 LangGraph 控制：接收需求 → 分配子任务 → 汇总结果 → 人工确认
- 内容子任务调用 CrewAI Crew：研究员+写手+编辑
- 代码子任务调用 AutoGen GroupChat：程序员+测试员

---

## ⚠️ 避坑指南

### ❌ 不要用 AutoGen 做……
- 需要精确流程控制的金融交易
- 长期运行、不能崩的后台服务
- 预算敏感的高频任务

### ❌ 不要用 CrewAI 做……
- 超过 15 个 Agent 的复杂系统
- 需要精细状态管理的任务
- 需要循环/递归逻辑的流程

### ❌ 不要用 LangGraph 做……
- 快速原型验证（除非你团队很强）
- 流程极其不确定的探索性任务
- 需要大量自由对话交互的场景

---

## 📌 终极建议

| 阶段 | 做什么 |
|------|--------|
| **Week 1** | 用 CrewAI 搭 MVP，验证方向 |
| **Week 2-3** | 如果 MVP 验证成功，评估是否需要 LangGraph 的精确控制 |
| **持续** | AutoGen 留给实验室、研究、Coding 辅助场景 |

> "先用 CrewAI 证明价值，再用 LangGraph 保证生产。" —— 这是 2025-2026 年最多团队验证过的路径。
